# 架构设计方案：跨平台桌面端 GIF 处理工具

## 1. 系统概述
本项目为一个独立的桌面端 GIF 处理软件，采用跨平台架构开发。系统在本地完成所有图像处理计算，无网络上传需求。核心处理能力通过在编译阶段静态内置多平台二进制引擎（如 FFmpeg、Gifsicle、ImageMagick）实现，达成开箱即用的软件分发模式。

## 2. 技术栈选型
* 开发语言: Kotlin
* UI 框架: Compose Multiplatform (JetBrains)
* 并发控制: Kotlin Coroutines (Dispatchers.IO / Dispatchers.Main)
* 底层进程调用: java.lang.ProcessBuilder
* 打包分发工具: Gradle (通过 org.jetbrains.compose 插件的 nativeDistributions 生成 .exe, .dmg, .deb)

## 3. 详细工程目录设计
工程采用标准 Compose Multiplatform 目录结构。以下为核心业务代码分布规约：

## 4. 核心功能模块设计规约

### 4.1 UI 布局与状态管理
* 主框架视图: 界面采用左右分栏设计。左侧为 NavigationRail，承载各功能模块切换入口；右侧为主工作区，通过 Crossfade 动态加载对应 Compose Tab 视图。
* 状态隔离与持久化: 使用 StateFlow 管理全局和局部状态。
    * 全局状态存储当前选中的源 GIF 路径、基础元数据。
    * 模块级状态存储各自表单的输入参数。切换 Tab 时，状态保存在上层级 ViewModel 或利用 rememberSaveable 机制，防止数据丢失。

### 4.2 引擎静态打包与运行时提取
Kotlin 进程无法直接执行安装包内部的二进制文件，需设计如下初始化解压流程：
1. 环境检测: EngineExtractor 在软件启动时调用 System.getProperty("os.name") 和 System.getProperty("os.arch") 确定宿主环境。
2. 临时目录映射: 确定解压目标路径（如 System.getProperty("java.io.tmpdir") + "/gif_app_engines/"）。
3. 流式释放: 通过 ClassLoader.getResourceAsStream 读取内置资源，利用输出流写入目标路径。
4. 权限赋予: 针对 macOS 和 Linux 系统，写入完成后调用 File.setExecutable(true) 确保可执行权限。此过程在主窗口加载前完成。

### 4.3 进程调度与并发规约
图像处理须严格限制在后台线程。
1. 调度策略: 涉及 ProcessBuilder.start() 及 .waitFor() 的方法，须使用 withContext(Dispatchers.IO) 包裹。
2. 参数拼接: 根据前端表单状态，在 Kotlin 层构建 List<String> 作为命令行执行参数。
3. 流捕获与反馈: 启动进程后，在独立协程中读取 Process.inputStream 和 Process.errorStream。解析终端输出日志，通过 MutableStateFlow 将进度回调至 Compose UI 线程更新状态。

## 5. 渐进式实施路线图

### 阶段一：基础骨架与引擎底座搭建
1. 初始化工程: 创建 Compose Desktop 项目，清理无用代码。
2. 配置 Gradle: 在 build.gradle.kts 中配置 nativeDistributions，设定目标输出格式。
3. 内嵌二进制引擎: 将多平台 FFmpeg 和 Gifsicle 可执行文件置入 desktopMain/resources/binaries/ 目录。
4. 实现环境解压模块: 编写 EngineExtractor.kt，实现 OS 检测、流提取与权限赋予逻辑，在 Main.kt 中添加启动调用。
5. 封装命令执行器: 编写 ProcessRunner.kt，实现接收参数并在 Dispatchers.IO 中执行，返回执行状态和输出文件路径。

### 阶段二：UI 框架搭建与通用组件
1. 构建 Navigation 框架: 实现左侧导航栏，包含一期模块（Resize, Crop, Rotate, Reverse, Speed, Optimize, Frames）的路由，以及二期模块的占位路由。
2. 实现通用状态展示区: 在主工作区顶部实现文件元数据展示组件，包含文件选择逻辑，选择后调用 ProcessRunner 获取图片宽高、帧数。
3. 实现底层结果展示区: 在主工作区底部实现统一的异步结果展示组件。

### 阶段三：一期核心功能业务集成 (按模块迭代)
一期实现包含 Resize, Crop, Rotate, Reverse, Speed, Optimize, Frames。依次执行以下标准开发流程：
1. UI 表单开发: 在对应 Tab 目录下（如 ResizeTab.kt）使用 Compose 编写数值输入框、下拉菜单、复选框。
2. 状态绑定: 将表单输入绑定至 MutableState。
3. 命令映射: 编写特定业务的命令生成器，将前端状态映射为底层 CLI 参数数组。
4. 联调测试: 触发协程，调用命令，捕获输出，渲染处理后的 GIF 文件至结果展示区。

### 阶段四：二期预留与打包发布
1. 二期占位: 确认 Effects, Add text, Censor, Add image, Cut, Split 的前端 Tab 已建立空视图组件。
2. 执行打包: 在不同操作系统的环境中执行 `./gradlew package`，生成最终安装包并验证独立运行情况。
