# 详细设计终稿：跨平台桌面端 GIF 处理工具

> 本文档为《基础需求文档.md》与《详细设计方案.md》的汇总定稿，已吸收评审确认结论。
> 关键决策变更点：引擎清单补齐、许可证合规说明、设置持久化、元数据工具选型、进度反馈降级为三态、旋转/Converter 引擎归属等。

---

## 1. 系统概述

本项目为一个独立的桌面端 GIF 处理软件，采用跨平台架构开发。系统在本地完成所有图像处理计算，无网络上传需求。核心处理能力通过在编译阶段静态内置多平台二进制引擎实现，达成开箱即用的软件分发模式。

**内置引擎清单（最终确认）：**

| 引擎 | 主要用途 | 许可证 |
| --- | --- | --- |
| FFmpeg（含 ffprobe） | 复杂变换、元数据读取、部分 GIF 处理 | LGPL-2.1+ / GPL（取决于编译开关） |
| Gifsicle | GIF 优化、裁剪、90° 步进旋转、翻转、延迟调整 | GPL-2.0 |
| ImageMagick | 任意角度旋转、画布扩展、色彩处理 | Apache-2.0（IM7） |
| gifski | 高质量 GIF 重编码（Reencode with gifski） | AGPL-3.0 |
| libvips | 高性能图像处理（Frames 模块 Converter 选项） | LGPL-2.1 |

---

## 2. 技术栈选型

- 开发语言：Kotlin
- UI 框架：Compose Multiplatform (JetBrains)
- 并发控制：Kotlin Coroutines (Dispatchers.IO / Dispatchers.Main)
- 底层进程调用：java.lang.ProcessBuilder
- 设置持久化：java.util.prefs.Preferences（JVM 内置，跨 Win/macOS/Linux）
- 打包分发工具：Gradle（org.jetbrains.compose 插件的 nativeDistributions 生成 .exe / .dmg / .deb）

## 3. 许可证合规说明（GPL-3.0 项目）

本项目以 **GPL-3.0** 协议开源。上述引擎均以**独立子进程**方式调用（ProcessBuilder），与 Kotlin 主程序之间仅通过命令行与标准流交互，不构成链接或衍生作品，属于 GPL 语境下的「聚合分发 (mere aggregation)」。因此各二进制各自保留原许可证，**不会**把 AGPL/GPL 传染到主程序代码。

**合规结论：可用，但需履行以下义务：**

1. 发行包内随附各引擎**对应版本的源码**（或书面要约 / 官方源码链接），尤其是：
   - Gifsicle（GPL-2.0）
   - FFmpeg（LGPL-2.1+ / GPL，需明确所分发构建的编译配置，如是否 `--enable-gpl` / `--enable-libx264` 等）
   - gifski（AGPL-3.0，五个引擎中要求最严格，须提供其二进制对应源码）
   - libvips（LGPL-2.1）
   - ImageMagick（Apache-2.0）
2. 随附各引擎的 LICENSE / COPYING 与版权声明文件。
3. 在项目 README 或 `THIRD_PARTY_NOTICES` 中列明第三方组件及其许可证。

> 注意：gifski 为 AGPL-3.0，虽因独立进程调用不影响主程序，但分发时必须提供其源码，不能省略。

## 4. 详细工程目录设计

工程采用标准 Compose Multiplatform 目录结构。核心业务代码分布规约如下：

```
project_root/
├── build.gradle.kts                 // 工程级构建脚本，含跨平台打包配置
├── src/
│   ├── commonMain/kotlin/           // 跨平台通用逻辑
│   │   ├── model/                   // 全局数据模型 (GifMetaData, ResizeConfig, CropConfig 等)
│   │   └── state/                   // 状态管理 (AppState 与各模块 StateHolder，视作 ViewModel 层)
│   └── desktopMain/
│       ├── kotlin/
│       │   ├── Main.kt              // 桌面端程序入口，定义 Window 及初始尺寸
│       │   ├── ui/
│       │   │   ├── layout/          // 主体布局 (NavigationRail, MainContentArea)
│       │   │   ├── components/      // 复用 UI 组件 (输入框、下拉菜单、ResultPreview 等)
│       │   │   └── tabs/            // 各功能模块面板 (ResizeTab, CropTab, FramesTab 等)
│       │   └── core/
│       │       ├── engine/          // 引擎管理
│       │       │   ├── EngineExtractor.kt   // 启动时二进制解压、存在性校验与可执行权限赋予
│       │       │   ├── ProcessRunner.kt     // 封装 ProcessBuilder 与标准流读取，返回三态结果
│       │       │   └── EngineType.kt        // 引擎枚举与可执行文件路径映射
│       │       ├── command/         // 命令生成器 (ResizeCommandBuilder, CropCommandBuilder 等)
│       │       ├── metadata/        // 元数据读取 (基于 ffprobe 的 GifMetaDataReader)
│       │       ├── settings/        // 设置持久化 (SettingsStore，基于 java.util.prefs.Preferences)
│       │       └── utils/           // 工具类 (OS 类型判断、文件流操作)
│       └── resources/               // 静态资源与引擎存放区
│           ├── binaries/
│           │   ├── windows/         // .exe 可执行文件
│           │   ├── macos/           // Unix 可执行文件 (推荐 Universal Binary)
│           │   └── linux/           // Linux 可执行文件
│           └── icons/               // 软件图标资源
```

> 引擎二进制需覆盖五个引擎（FFmpeg 发行包内含 ffprobe），按平台分目录放置。ImageMagick 使用 IM7 的 `magick` 命令（或兼容别名 `convert`）。

## 5. 核心功能模块设计规约

### 5.1 UI 布局与状态管理

- **主框架视图**：界面采用左右分栏设计。左侧为 NavigationRail，承载各功能模块切换入口；右侧为主工作区，通过 Crossfade 动态加载对应 Compose Tab 视图。
- **状态隔离与持久化**：使用 StateFlow 管理全局和局部状态。
  - 全局状态（`AppState`）：存储当前选中的源 GIF 路径、基础元数据。
  - 模块级状态（各 `StateHolder`，位于 `state/` 包，视作 ViewModel 层）：存储各自表单的输入参数。切换 Tab 时状态保存在上层级 StateHolder，防止数据丢失。

### 5.2 设置持久化（「Remember settings」）

「记忆用户操作习惯」要求**跨会话**持久化，`rememberSaveable` 仅限会话内内存态、无法满足，故引入文件级持久化：

- 使用 `java.util.prefs.Preferences`（JVM 内置，跨 Windows 注册表 / macOS plist / Linux 配置文件），由 `core/settings/SettingsStore.kt` 统一封装读写。
- 勾选「Remember settings」后，当前模块的表单参数在变更时写入 Preferences；下次启动时回填。
- 引擎可执行文件的解压路径等运行时配置也由 SettingsStore 管理。

### 5.3 引擎静态打包与运行时提取

Kotlin 进程无法直接执行安装包内部的二进制文件，需设计如下初始化解压流程：

1. **环境检测**：EngineExtractor 在软件启动时调用 `System.getProperty("os.name")` 与 `System.getProperty("os.arch")` 确定宿主环境，映射到对应平台二进制。
2. **临时目录映射**：确定解压目标路径（如 `System.getProperty("java.io.tmpdir") + "/gif_app_engines/"`）。
3. **流式释放**：通过 `ClassLoader.getResourceAsStream` 读取内置资源，利用输出流写入目标路径。
4. **权限赋予**：针对 macOS 和 Linux，写入完成后调用 `File.setExecutable(true)` **赋予可执行权限（chmod +x）**。此过程在主窗口加载前完成。
5. **存在性校验**：由于临时目录可能被系统清理，每次执行进程前校验目标二进制是否存在，缺失则重新释放。

> 说明：本处语义为「赋予可执行权限」，非「提权（获取管理员/root 权限）」。

### 5.4 进程调度与并发规约

图像处理须严格限制在后台线程。

1. **调度策略**：涉及 `ProcessBuilder.start()` 及 `.waitFor()` 的方法，须用 `withContext(Dispatchers.IO)` 包裹。
2. **参数拼接**：根据前端表单状态，在 Kotlin 层构建 `List<String>` 作为命令行参数，避免字符串拼接导致的注入问题。
3. **流捕获与防死锁**：启动进程后，在独立协程中**同时**读取 `Process.inputStream` 与 `Process.errorStream`，避免缓冲区满导致进程挂起。
4. **状态反馈（三态，无进度条）**：以密封类 `TaskStatus` 表达 `Idle / Running / Success / Failed`，通过 `MutableStateFlow` 回调至 Compose UI。除 FFmpeg 外的大多数命令不输出可解析进度，故 UI 仅做「处理中 → 成功 / 失败」两态展示，不做实时进度。

### 5.5 元数据读取

文件元数据（体积、宽度、高度、总帧数、格式、总时长）**统一使用 ffprobe** 读取：

- ffprobe 随 FFmpeg 一并分发，无需额外二进制。
- 输出 JSON（`ffprobe -v error -print_format json -show_format -show_streams`），便于解析 `format.size`（体积）、`width/height`、`nb_frames`、`format_name`、`duration`（时长）。
- 由 `core/metadata/GifMetaDataReader.kt` 封装，供全局状态与各 Tab 调用。

### 5.6 结果展示区（跨模块共享）

- 提供一个可复用的 `ResultPreview` 组件（位于 `ui/components/`），每个 Tab 页面**底部**统一渲染该组件。
- 组件内部根据 `TaskStatus` 渲染三种状态：处理中（加载态）、成功（展示处理后的 GIF）、失败（错误提示文本）。
- 各 Tab 复用同一实现，避免重复开发。

## 6. 一期功能模块详细规约

> 每个模块统一包含：文件元数据展示、异常处理提示（建议先 unoptimize）、「Remember settings」复选框、底部结果展示区。

### 6.1 调整大小 (Resize)

- **尺寸输入**：
  - Width / Height：输入具体像素值。
    - 单侧留空：按原图比例自动计算另一侧（等比缩放）。
    - 双侧填写：按目标尺寸直接缩放，比例不一致时**拉伸变形**（即「尺寸重构 / 画布压缩」），**不是裁剪**。
  - Percentage：按百分比等比例缩放。
- **处理方法选择 (Resize method)**：
  - Gifsicle (fastest, smallest file size)
  - ImageMagick
  - ImageMagick + coalesce (undo optimizations)
  - Change canvas size (add padding without scaling)（加边距、不缩放）
- **执行操作**：Resize image! 按钮。

> 变更说明：原需求中「长宽比不匹配策略（Center and crop to fit）」属于裁剪语义，已从 Resize 移除；裁剪能力统一归 Crop 模块。

### 6.2 裁剪 (Crop)

- **画布视图控制（预览）**：
  - 背景显示 (Background)：下拉菜单（当前截图选项为 Checkered pattern，用于显示透明底）。
  - 预览缩放控制：提供「don't scale large images」复选框。
- **裁剪参数**：提供 Left、Top、Width、Height 四个数值输入框，前端配合可视化拖拽选框联动更新数值。
- **锁定长宽比 (Lock aspect ratio)**：下拉菜单限制裁剪比例。
- **处理引擎选择 (Crop with)**：下拉菜单（当前截图选项为 Gifsicle）。
- **自动裁剪 (Autocrop)**：「trim transparent pixels around the image」复选框，自动去除透明边缘。
- **执行操作**：Crop image! 按钮。

> 变更说明：原「扩展画布 (Extend canvas size)」按钮已移除，画布扩展能力统一由 Resize 的「Change canvas size」承担。

### 6.3 旋转与翻转 (Rotate)

- **翻转控制 (Flip)**：垂直翻转 (flip vertical)、水平翻转 (flip horizontal) 复选框。
- **旋转控制 (Rotate)**：
  - 顺时针 90° / 逆时针 90° / 180°
  - 自定义角度 (rotate [ ] degrees)：复选框配合数值输入框。
- **执行操作**：Apply rotation! 按钮。

**引擎归属（评审确认）：**

| 操作 | 引擎 |
| --- | --- |
| 90° / 180° / 翻转 | Gifsicle（原生支持，无损、保留动画） |
| 自定义任意角度 | ImageMagick（需先 coalesce，避免动画帧错位） |

### 6.4 倒放与播放控制 (Reverse)

- **时间轴控制**：
  - 倒放 (reverse)
  - 修改循环次数 (change the number of times to play / loop)
  - 回旋镖效果 (run to the end and reverse back to the start / boomerang)
  - 添加计时器 (add second counter)：在画面上叠加显示当前 GIF 动画的**已播放时长**、逐秒递增的计时器（**跨模块共享能力**，多个菜单中复用）。
- **翻转控制 (Flip)**：垂直翻转、水平翻转复选框（复用 Rotate 模块相关逻辑）。
- **执行操作**：Submit! 按钮。

### 6.5 速度调整 (Speed)

- **全局速度调节**：
  - 目标速度数值输入框。
  - 调节模式下拉菜单：`% of current speed`（当前速度百分比）或 `hundredths of second between frames`（帧间绝对延迟，单位 1/100 秒）。
- **单帧精细控制**：「Customize delay for individual frames」复选框，勾选后展示单帧延迟独立设定界面。
- **执行操作**：Change speed! 按钮。

### 6.6 优化与压缩 (Optimize)

- **优化方法选择 (Optimization method)**：分组下拉菜单：
  - Lossy GIF compression（有损压缩）：Lossy GIF、Reencode with gifski
  - Combined（组合）：Combined: remove duplicates + transparency + lossy
  - Color Reduction（色彩减少）：Color Reduction、Color Reduction + dither、Use single color table for all frames
  - Drop frames（抽帧）：Remove duplicate frames、按固定间隔抽帧（2nd / 3rd / 4th frame）
  - Transparency（透明度）：Optimize Transparency
  - Coalesce（合并/解除优化）：Coalesce (unoptimize)
- **特定参数设置（随方法动态切换）**：
  - 压缩级别 (Compression level)：范围滑块 + 关联数值输入框。
  - 消除局部色彩表 (Eliminate local color tables)：复选框。
- **执行操作**：Optimize GIF! 按钮。

**引擎归属：** 主要使用 Gifsicle / ImageMagick；「Reencode with gifski」使用 gifski。

### 6.7 帧管理与合成 (Frames)

- **新增帧入口**：`+ Upload more frames` 按钮，向当前序列追加图像文件。
- **单帧可视化与控制 (Frame Grid)**：
  - 网格按顺序展示所有帧缩略图。
  - 每帧参数：Delay 数值输入框（单位 1/100 秒）。
  - 每帧操作：Skip（跳过剔除）、Copy（复制）按钮。
- **批量帧操作 (Toggle a range of frames)**：
  - 按区间：From [ ] To [ ]，配合 Skip range / Enable range。
  - 按步长：Every [ ]，配合 Skip every N-th / Enable every N-th。
- **全局 GIF 选项 (GIF options)**：
  - 全局统一延迟 (Delay time)：数值输入框，实时换算显示 FPS 估值。
  - 循环次数 (Loop count)：输入框，留空代表无限循环。
  - 全局调色板 (use global colormap)：复选框。
  - 转换引擎 (Converter)：下拉菜单，**三个选项（评审确认）**：
    1. libvips
    2. ImageMagick
    3. ImageMagick (-color 256)
- **帧叠加与特效 (Effects)**：
  - crossfade frames：复选框。
  - don't stack frames：复选框，勾选后解锁子选项「use the first frame as background」。
- **执行操作**：Make a GIF! 按钮。

## 7. 二期预留功能模块

前端顶部 Tab 导航栏需完整保留以下选项卡的 DOM 结构与样式作为占位符，一期暂不实现内部业务逻辑：

- **Effects（特效）**：颜色滤镜、灰度转换等。

- **Add image（添加图像）**：在特定帧叠加水印或其它图片。
- **Cut（剪辑）**：截取 GIF 的特定时间段。
- **Split（拆分）**：将动态 GIF 拆分为独立静态图片集合。

## 8. 渐进式实施路线图

### 阶段一：基础骨架与引擎底座搭建

1. 初始化工程：创建 Compose Desktop 项目，清理无用代码。
2. 配置 Gradle：在 build.gradle.kts 中配置 nativeDistributions，设定目标输出格式。
3. 内嵌二进制引擎：将 **FFmpeg（含 ffprobe）、Gifsicle、ImageMagick、gifski、libvips** 五个引擎的多平台可执行文件置入 `desktopMain/resources/binaries/` 目录。
4. 实现环境解压模块：编写 EngineExtractor.kt，实现 OS 检测、流提取、**可执行权限赋予**、存在性校验与重新释放，在 Main.kt 中添加启动调用。
5. 封装命令执行器：编写 ProcessRunner.kt，实现接收参数并在 Dispatchers.IO 中执行，返回 `TaskStatus`（三态）与输出文件路径。
6. 实现元数据读取：编写 GifMetaDataReader.kt，基于 ffprobe 读取宽高、帧数、时长、体积、格式。
7. 实现设置持久化：编写 SettingsStore.kt，封装 java.util.prefs.Preferences。

### 阶段二：UI 框架搭建与通用组件

1. 构建 Navigation 框架：左侧导航栏包含一期模块（Resize, Crop, Rotate, Reverse, Speed, Optimize, Frames）路由 + 二期模块（Effects, Add text, Censor, Add image, Cut, Split）占位路由。
2. 实现通用状态展示区：主工作区顶部实现文件元数据展示组件，含文件选择逻辑，选择后调用 GifMetaDataReader 获取元数据。
3. 实现底层结果展示区：主工作区底部实现统一的 ResultPreview 异步结果展示组件（复用，承载三态）。

### 阶段三：一期核心功能业务集成（按模块迭代）

依次对 Resize, Crop, Rotate, Reverse, Speed, Optimize, Frames 执行标准流程：

1. UI 表单开发：在对应 Tab 目录（如 ResizeTab.kt）使用 Compose 编写数值输入框、下拉菜单、复选框。
2. 状态绑定：将表单输入绑定至 MutableState。
3. 命令映射：在 `core/command/` 下编写特定业务的命令生成器，将前端状态映射为底层 CLI 参数数组（含引擎选择逻辑，如 Rotate 的 90° 走 Gifsicle、任意角度走 ImageMagick）。
4. 联调测试：触发协程、调用命令、捕获输出，渲染处理后的 GIF 至 ResultPreview。

### 阶段四：二期预留与打包发布

1. 二期占位：确认 Effects, Add text, Censor, Add image, Cut, Split 的 Tab 已建立空视图组件。
2. 执行打包：在不同操作系统的环境中执行 `./gradlew package`，生成最终安装包并验证独立运行。
3. 许可证合规收尾：在发行包与 README/THIRD_PARTY_NOTICES 中随附五个引擎的 LICENSE、版权声明及对应源码（或源码要约链接）。
